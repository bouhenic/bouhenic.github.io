Modulation LoRa — Chirp Spread Spectrum (CSS)

Fréquence  ▲
868.0625 ─│    ╱│    ╱│
          │   ╱ │   ╱ │   ← up-chirp
868.0000 ─│  ╱  │  ╱  │     fréquence centrale (canal)

867.9375 ─│╱    │╱    │
          └──────────────▶ Temps
          Bande passante = 125 kHz (standard)
Un chirp = signal dont la fréquence monte linéairement
sur toute la bande passante pendant la durée d'un symbole.
SF bits encodés dans la fréquence de départ du chirp.

SF2 — 2 bits/symbole → 4 symboles possibles (2² = 4)

F haute F basse
"00"
départ Fmin
"01"
départ +¼ BW
"10"
départ +½ BW
"11"
départ Fmax
◀── durée symbole Ts (identique pour tous) ──▶
Principe : même durée Ts, même BW — seule la fréquence de départ change pour encoder les bits. Le récepteur mesure ce point de départ pour décoder.
─ ─ = wrap cyclique : quand le chirp atteint Fmax, il reprend de Fmin.

Spreading Factor (SF) — Impact sur le réseau

SFBits/symboleTs (125 kHz)PortéeDébit
SF7 7 bits → 128 symboles 1,02 ms Courte 5,47 kbps
SF8 8 bits → 256 symboles 2,05 ms 3,13 kbps

SF10 10 bits → 1024 symboles 8,19 ms 980 bps

↑ SF → ↑ portée, ↑ sensibilité, ↓ débit, ↑ durée TX, ↓ autonomie batterie
Orthogonalité : des SF différents sur le même canal ne se brouillent pas.
ADR (Adaptive Data Rate) : le serveur ajuste automatiquement le SF.

Classes d'objets LoRaWAN

A
Le Plus Économe
Émission uplink à la demande
Ouvre 2 fenêtres RX courtes après TX
Reste en veille le reste du temps

→ Capteurs batterie : T°, humidité
TX → RX1(1s) → RX2(2s) → 💤
B
L'Équilibré
Classe A + ping slots programmés

→ Contrôle régulier, irrigation

Le Plus Réactif
RX continu (sauf pendant TX)
Latence downlink quasi-nulle
Alimentation continue requise

→ Actionneurs : éclairage, pompe

Sécurité LoRaWAN — Deux clés AES-128

NwkSKey
Authenticité + Intégrité
Partagée entre Device LoRa ↔ Network Server uniquement. 
Device                    Network Server
NwkSKey ─→ aes128_cmac ─→ MIC émis
données chiffrées  │      MIC reçu  │
───────────────────┘──────────────────
Si MIC émis == MIC reçu → trame authentifiée
La Gateway ne connaît pas NwkSKey · Protège contre la falsification
AppSKey
Confidentialité
Partagée entre Device LoRa ↔ Application Server uniquement. 
Device                     App Server
Données brutes
  └→ AES-128 encrypt(AppSKey)
       └→ Payload chiffré ─────────→
                              AES-128 decrypt(AppSKey)
                                └→ Données lisibles
Ni Gateway, ni NS ne peuvent lire le payload → chiffrement bout-en-bout
Anti-Replay Compteur de trame (FCnt)
Chaque trame émise incrémente le FCnt. Le NS rejette toute trame avec
un FCnt ≤ dernier FCnt reçu → protection contre l'attaque de Replay.

Activation des Devices — ABP vs OTAA

ABP — Activation By Personalization
Méthode statique — configuration manuelle
⚠ Moins sécurisé
DEVICE LoRa
DevAddr ← identifiant réseau
AppSKey ← chiffrement (fixe)
NwkSKey ← auth (fixe)
NETWORK + APP SERVER
DevAddr
AppSKey
NwkSKey
✓ Simple · Pas de procédure Join · Fonctionne immédiatement
✗ Clés fixes → si compromises, toutes les sessions sont compromises
OTAA — Over The Air Activation
Méthode dynamique — négociation des clés
✓ Recommandé
DEVICE (identifiants permanents)
DevEUI ← ID matériel unique
AppEUI/JoinEUI ← ID application
AppKey ← clé racine secrète
PROCÉDURE JOIN
1 Join Request (DevEUI, AppEUI, DevNonce)
→ NS vérifie + génère AppNonce
2 Join Accept chiffré (AppNonce, NetID, DevAddr) 
NwkSKey = aes128_encrypt(AppKey, 0x01 | AppNonce | NetID | DevNonce | pad16)
AppSKey = aes128_encrypt(AppKey, 0x02 | AppNonce | NetID | DevNonce | pad16)
✓ Clés de session uniques et renouvelables à chaque Join · Très sécurisé
! Nécessite couverture réseau pour le Join initial

Mise en œuvre pratique — Configuration ChirpStack (OTAA)

Étape 1 Gateway → Serveur
Configurer l'IP/domaine du LoRaWAN Server dans l'interface web de la gateway.

Enregistrer la gateway sur ChirpStack avec son EUI 64 bits (étiquette).
Étape 2 Créer Application
Sur ChirpStack : créer une application (ex. "Capteurs Météo").

Chaque application isole les devices et leurs données.
Étape 3 Enregistrer Device
DevEUI → lire sur étiquette (Dragino) ou Serial Monitor (Arduino)
AppEUI → souvent 0x0000…0001
AppKey → générer aléatoirement sur ChirpStack
Étape 4 Flasher le Device
Copier AppKey générée dans le code Arduino :
String appKey = "F4E3D2...";
// Téléverser → Join automatique
