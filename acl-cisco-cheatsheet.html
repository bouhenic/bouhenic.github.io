CONCEPT FONDAMENTAL
Une ACL est une liste ordonnée de règles configurée sur un routeur Cisco pour filtrer le trafic réseau.
Le routeur examine les en-têtes de chaque paquet et les compare séquentiellement jusqu'à trouver une correspondance.
IP Source IP Destination Protocole N° de Port
⚠ Une seule ACL par interface, par direction (in / out)
⚠ Les paquets générés par le routeur lui-même ne sont pas filtrés

MASQUE GÉNÉRIQUE (WILDCARD MASK)
Masque inversé du sous-réseau : 0 = bit fixe (doit correspondre) · 1 = bit ignoré (peut varier)
255.255.255.255 – 255.255.255.0 (masque de sous-réseau classique) ───────────────────────────── = 0.0.0.255 (wildcard mask résultant)
Raccourcis IOS :
host 192.168.1.10 = 192.168.1.10 0.0.0.0 # hôte unique any = 0.0.0.0 255.255.255.255 # tous les hôtes
Exemples de calcul :
192.168.1.0/24→ WC: 0.0.0.255dernier octet libre

Caractéristique ACL Standard ACL Étendue
Identifiants 1–99 · 1300–1999 100–199 · 2000–2699

Placement optimal Au plus près de la destination Au plus près de la source
Raison du placement Ne filtre que la source → bloquerait vers toutes destinations si placée trop tôt Précise → détruit le trafic dès l'origine, économise la bande passante

Protocole ciblé Non (ip implicite) Oui : ip, tcp, udp, icmp, ospf...
Ports filtrés Non Oui : eq, gt, lt, neq, range

SCÉNARIOS — ACL STANDARD · (IDs 1–99) · placement au plus près de la DESTINATION
Cas 1 — Bloquer un hôte spécifique
PC1 (192.168.1.10) isolé du réseau distant
# ACL access-list 10 deny host 192.168.1.10 access-list 10 permit any # Application interface G0/1 ip access-group 10 out
Cas 2 — Autoriser uniquement un serveur
Seul 192.168.1.100 peut communiquer
# ACL access-list 20 permit host 192.168.1.100 access-list 20 deny any # Application interface G0/1 ip access-group 20 out
Cas 3 — Préserver la bande passante
Bloquer des hôtes dès l'entrée (inbound)
# ACL access-list 40 deny host 192.168.1.10 access-list 40 deny host 192.168.1.11 access-list 40 permit any # Application (inbound !) interface G0/0 ip access-group 40 in
Cas 4 — Sécuriser l'accès SSH (VTY)
Seuls les admins 192.168.1.50/.51 via SSH
# ACL access-list 30 permit host 192.168.1.50 access-list 30 permit host 192.168.1.51 access-list 30 deny any # Application sur VTY ! line vty 0 4 access-class 30 in
SCÉNARIOS — ACL ÉTENDUE · (IDs 100–199) · placement au plus près de la SOURCE
Cas 1 — Bloquer HTTP (port 80)
Empêcher 192.168.1.0/24 d'accéder au web
access-list 101 deny tcp 192.168.1.0 0.0.0.255 any eq 80 access-list 101 permit ip any any interface G0/1 ip access-group 101 in
Cas 2 — Isolation MySQL (port 3306)
Seul 192.168.1.100 accède à la BDD
access-list 102 permit tcp host 192.168.1.100 host 192.168.3.200 eq 3306 access-list 102 deny tcp any any eq 3306 interface G0/1 ip access-group 102 in
Cas 3 — Réseau invisible au Ping
Bloquer ICMP echo depuis l'extérieur
access-list 103 deny icmp 192.168.2.0 0.0.0.255 192.168.1.0 0.0.0.255 echo access-list 103 permit ip any any interface G0/0 ip access-group 103 in
Cas 4 — SSH chirurgical (port 22)
Admins SSH uniquement vers l'IP du routeur
access-list 104 permit tcp host 192.168.1.50 host 192.168.1.1 eq 22 access-list 104 permit tcp host 192.168.1.51 host 192.168.1.1 eq 22 access-list 104 deny ip any any
Scénario avancé — Sécurisation stricte d'une DMZ (192.168.3.0/24) : HTTP et HTTPS publics, tout le reste bloqué
# ACL 105 — Nommée étendue recommandée ip access-list extended DMZ_PUBLIC 10 permit tcp any 192.168.3.0 0.0.0.255 eq 80 # Autoriser HTTP 20 permit tcp any 192.168.3.0 0.0.0.255 eq 443 # Autoriser HTTPS 30 deny ip any 192.168.3.0 0.0.0.255 # Bloquer tout autre trafic vers DMZ 40 permit ip any any # Maintenir la circulation globale R1(config)# interface G0/2 R1(config-if)# ip access-group DMZ_PUBLIC in
L'ARCHITECTURE IMPECCABLE — 4 RÈGLES D'OR
01
Spécifique Avant Général
First match : placer toujours les règles ciblées avant les règles larges (permit any, deny any). Une règle générale en tête court-circuite tout le reste.
deny host 192.168.1.10 ← spécifique permit any ← général
02
L'Implicite est Fatal
Toute ACL se termine par un deny any invisible. Si vous oubliez le permit any final (ou les règles nécessaires), tout le trafic résiduel est détruit silencieusement.
deny host 10.0.0.1 permit any ← porte de secours ! ! implicit deny all ←invisible
03
La Loi du Placement
Standard → au plus près de la destination : filtre uniquement la source, évite les dommages collatéraux.
Étendue → au plus près de la source : détruit le trafic dès l'origine, préserve la bande passante.
04
La Porte de Secours
Ajoutez systématiquement permit ip any any en fin d'ACL étendue si vous ne souhaitez pas isoler complètement l'infrastructure. Testez toujours avec show access-lists avant et après.
