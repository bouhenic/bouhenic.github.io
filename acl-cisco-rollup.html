▸ Fondamentaux
CONCEPT FONDAMENTAL
Une ACL est une liste ordonnée de règles configurée sur un routeur Cisco pour filtrer le trafic réseau.
Le routeur examine les en-têtes de chaque paquet et les compare séquentiellement jusqu'à trouver une correspondance.
IP Source IP Destination Protocole N° de Port
⚠ Une seule ACL par interface et par direction (in / out)
⚠ Les paquets générés par le routeur lui-même ne sont pas filtrés
⚠ L'ordre des règles est critique — toujours tester après modification
LOGIQUE SÉQUENTIELLE
First match — de haut en bas, sans retour :
Règle 10
→ no match → continue
Règle 20
→ no match → continue
Règle 30
✓ MATCH → action, stop
⛔ Implicit Deny All — règle invisible finale · tout trafic non matché est détruit

▸ Scénarios Standard · placement DESTINATION
Cas 1 — Bloquer un hôte spécifique
PC1 (192.168.1.10) isolé du réseau distant
access-list 10 deny host 192.168.1.10 access-list 10 permit any interface GigabitEthernet0/1 ip access-group 10 out
Cas 2 — Autoriser uniquement un serveur
Seul 192.168.1.100 peut communiquer
access-list 20 permit host 192.168.1.100 access-list 20 deny any interface GigabitEthernet0/1 ip access-group 20 out
Cas 3 — Préserver la bande passante
Bloquer plusieurs hôtes dès l'entrée
access-list 40 deny host 192.168.1.10 access-list 40 deny host 192.168.1.11 access-list 40 permit any interface GigabitEthernet0/0 ip access-group 40 in
Cas 4 — Sécuriser SSH (VTY)
Seuls les admins .50 et .51 autorisés
access-list 30 permit host 192.168.1.50 access-list 30 permit host 192.168.1.51 access-list 30 deny any line vty 0 4 access-class 30 in
▸ Scénarios Étendus · placement SOURCE
Cas 1 — Bloquer HTTP (port 80)
Réseau .1.0/24 sans accès aux serveurs web
access-list 101 deny tcp 192.168.1.0 0.0.0.255 any eq 80 access-list 101 permit ip any any interface GigabitEthernet0/1 ip access-group 101 in
Cas 2 — Isoler MySQL (port 3306)
Seul 192.168.1.100 accède à la BDD
access-list 102 permit tcp host 192.168.1.100 host 192.168.3.200 eq 3306 access-list 102 deny tcp any any eq 3306
Cas 3 — Réseau invisible au Ping
Bloquer ICMP echo depuis l'extérieur
access-list 103 deny icmp 192.168.2.0 0.0.0.255 192.168.1.0 0.0.0.255 echo access-list 103 permit ip any any interface GigabitEthernet0/0 ip access-group 103 in
Cas 4 — SSH chirurgical (port 22)
Admins .50/.51 vers IP exacte du routeur
access-list 104 permit tcp host 192.168.1.50 host 192.168.1.1 eq 22 access-list 104 permit tcp host 192.168.1.51 host 192.168.1.1 eq 22 access-list 104 deny ip any any
AVANCÉ — DMZ STRICTE (HTTP+HTTPS publics, tout le reste bloqué)
ip access-list extended DMZ_PUBLIC 10 permit tcp any 192.168.3.0 0.0.0.255 eq 80 20 permit tcp any 192.168.3.0 0.0.0.255 eq 443 30 deny ip any 192.168.3.0 0.0.0.255 40 permit ip any any R1(config-if)# ip access-group DMZ_PUBLIC in
▸ L'Architecture Impeccable — 4 Règles d'Or
01
Spécifique Avant Général
First match : les règles ciblées doivent toujours précéder les règles larges. Une règle générale en tête court-circuite intégralement le reste.
deny host 192.168.1.10 ← spécifique d'abord permit any ← général en dernier
02
L'Implicite est Fatal
Toute ACL se termine par un deny any invisible. Oublier le permit any final détruit silencieusement tout trafic résiduel — y compris SSH admin !
deny host 10.0.0.1 permit any ← porte de secours obligatoire ! implicit deny ← invisible, toujours présent
03
La Loi du Placement
Standard → interface la plus proche de la destination : filtre la source, évite les dommages collatéraux.

Étendue → interface la plus proche de la source : détruit le trafic indésirable à l'origine, préserve la bande passante.
04
La Porte de Secours
Ajoutez systématiquement permit ip any any en fin d'ACL étendue si vous ne souhaitez pas isoler l'infrastructure. Testez toujours avec show access-lists.
